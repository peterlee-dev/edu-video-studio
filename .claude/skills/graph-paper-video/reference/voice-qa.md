# TTS 내레이션 검수: 받아쓰기가 놓치는 것

`make_audio.py tts` 는 whisper 로 받아써서 대본을 글자 그대로 읽은 테이크를 골라요. 그런데 **whisper 는 들어야 할 말을 알고 있으면 틀리게 읽은 것도 맞게 적어요.** 아래는 검토에서 실제로 지적받았는데 받아쓰기 검사를 통과했던 것들이에요. 새 영상을 넘기기 전에, 그리고 문장을 다시 읽힌 뒤에 확인해요.

도구는 `tools/voice_check.py` 하나예요(맨 위 설명 참고). 고른 테이크를 바꿀 때는 `tools/script.py` 의 `TAKE = {'l3_2': 7}` 로 고정해요. 숫자는 `voice_check.py takes` 가 출력한 번호(정렬된 순서)이고 파일 이름의 번호가 아니에요(`_10` 이 `_2` 보다 앞에 와요).

## 1. 문장 끝이 잘림

- 증상: 마지막 음절이 툭 끊기거나 마지막 단어 끝소리가 없어요(evidence → "evidenc", U.S. → "U.", growth → "gro"). 검토 의견 "tts 짤림"
- 원인: TTS 서버가 말소리가 끝나는 순간 출력을 끊어요. 문장을 세게 끝내는 목소리(광고 내레이션)에서 심하고, 기준 녹음이 단어 끝에서 바로 잘려 있어도 심해요
- 이미 들어간 대책: `make_audio.py` 가 문장마다 뒤에 짧은 문장(`TAIL_TEXT`: 한국어 "감사합니다.", 영어 "Thank you.")을 붙여 읽히고 그 앞 쉼에서 잘라내요. 그러면 문장 끝이 말 중간의 문장처럼 자연스럽게 떨어지고 0.2초쯤 여유가 남아요. 그래도 소리 도중에 끝나는(마지막 30 ms 가 큰) 테이크와 끝 무음이 0.2초 안 되는 테이크는 `cut` 으로 쳐서 고르지 않아요
- 확인: `make_audio.py` 출력의 `tail` 과 `[0 0c 1]` 의 `c`. `! l3_2: every take ends mid-sound` 가 나오면 `N=8 … tts --redo l3_2`
- 그래도 안 되면: 읽는 문장 끝을 `" ..."` 로(소리 내지 않는 쉼). "U-S." · "U. S." · "United States." 로 바꾸는 것은 효과가 없었어요
- 문장이 다음 문장으로 이어지는 조각이면(대본이 한 문장을 두 줄로 나눈 경우) 읽는 문장 끝에 쉼표를 둬요. 그래야 붙인 문장 앞에서 잘라낼 쉼이 생겨요

## 2. 한 문장만 톤이 낮음 / 문장 중간에 톤이 떨어짐

- 증상: 검토 의견 "음성 이상함 (갑자기 톤이 낮아짐)". 복제 목소리가 가끔 한 테이크를 낮은 목소리로 읽어요(다른 문장 155–190 Hz 인데 그 문장만 124 Hz). 문장 중간부터 떨어지기도 해요(2초 구간 171 161 126 126)
- 확인: `voice_check.py pitch` → `!` 가 붙은 줄을 들어 봐요. 새로 읽힌 문장도 같은 확인을 해요(새 문장 첫 테이크 3개 중 2개가 끝에서 126 Hz 로 떨어진 적이 있어요)
- 고치기: `N=8 … tts --redo <id>` → `voice_check.py takes <id>` 로 높이가 고른 테이크를 골라 `TAKE` 로 고정

## 3. 끝인사가 올라감

- 증상: 마지막 "Thank you" · "감사합니다" 가 질문처럼 끝이 올라가요(98 → 187 Hz). 검토 의견 "끝이 내려가게"
- 확인 · 고치기: `N=12 … --redo <id>` 로 10개쯤 읽혀서 `voice_check.py takes <id>` 의 `end` 가 몇 반음 아래로(음수) 떨어지는 테이크를 골라요. 여자 목소리는 "you" 끝 50 ms 에서 다시 튀어 오르는 테이크가 많아서(14개 중 13개), 끝까지 내려가 있는 것을 골라요. 그다음 발음(아래 4)과 끝 잘림(1)도 확인
- 음 높이 범위: 남자 목소리에 상한 300 Hz 를 쓰면 Praat 가 한 옥타브 위로 잘못 잡아서 올라간 것처럼 보여요. `voice_check.py` 는 기준 녹음 높이의 1.6배를 상한으로 써요. 여자 목소리 끝은 80–100 Hz 로 갈라져서 하한은 75 Hz

## 4. 발음

- 증상: whisper 는 맞게 적었는데 사람이 들으면 틀린 발음. 실제 예: POD → "pod" · "페오디", Reading Comprehension → "Donprehension", Knowledge Map → "놀리지 매프"(콩글리시), 실선은 → "시선은", ChatGPT → 음절이 하나 더("챗지지피티")
- 확인: `voice_check.py phonemes <id> [A B]` 가 wav2vec2(`facebook/wav2vec2-lv-60-espeak-cv-ft`)로 테이크를 음소(IPA)로 풀어 줘요. 이게 검토 지적과 정확히 맞았어요. 한국어는 whisper 의 단어 시각이 흔들려서 단어만 잘라 내면 잘못 풀려요: 테이크 전체나 2–3초 구간을 풀어서 그 이름 근처를 읽어요
- 좋은 예 / 나쁜 예(음소):
  - JEI(제이이아이) ≈ `tʃ aɪ iː aɪ (iː)` / 나쁨 `tʃ aɪ aɪ`(제아이)
  - POD(피오디) ≈ `p iː o d iː` / 나쁨 `p uː d i`(푸디), `pʰ i t i`(피디)
  - 맵 기반 = `m e p k i b a n`, p 뒤에 모음이 없어야(맵 → "매프" 아님)
  - Knowledge 는 `n ɑ l…`("놀" 아님). 읽는 문장에 Knowledge 는 영어 그대로, Map 은 "맵"
  - ChatGPT ≈ `tɕh a tɕ i p i t i` / 나쁨 `tɕh a tɕ i tɕ i p i t i`. whisper 는 이 단어를 언제나 "채찌 PT" 처럼 적어서 받아쓰기 불일치는 다시 읽을 이유가 아니에요
  - 실선은 = `s i r s ɔ n ə n`(ㄹ 이 있어야) / 나쁨 `s ø s ɔ n`
- 고치는 방법: 맞게 읽은 테이크를 `TAKE` 로 고정. 없으면 읽는 문장을 바꿔요
  - 약어는 한 글자씩: "P-O-D", "J-E-I". 한국어 영상은 소리대로: 지이오, 피오디
  - 된소리: 진단평가 → 진단평까, 강점 → 강쩜, 교점 → 교쩜(`SAY` 로 한 번에)
  - 두 단어가 붙어 이상하게 읽히면 쉼표(Reading, Comprehension). 단, 쉼표를 넣으면 대부분 그 자리에서 쉬어요("한 단어처럼 읽어야 함, 쉬는 텀이 너무 길어"): 발음도 맞고 두 단어 사이 무음이 0.05초 안 되는 테이크를 골라요
- 화면 큐(`Wc`)는 whisper 가 적은 철자로 찾아요: 읽는 형태를 바꿨으면 큐에 두 철자를 다 넣어요(`['pod', 'p']`)

## 5. 쉼 · 빠르기

- "단어 사이사이에 쉼", "숨 쉴 틈" 같은 의견은 **쉼표와 간격으로만** 고쳐요(읽는 문장에 쉼표, `GAP` · `SCENE_GAP` · 문장 뒤 쉼). 목소리 속도(`TEMPO`)는 1 그대로. 0.93 으로 늦췄다가 "음성 속도가 너무 느려졌는데? 속도는 이전이 나아" 로 되돌린 적이 있어요. 빠르기를 바꾸는 게 낫겠다 싶으면 먼저 물어봐요
- 한 문장을 많이 다시 읽히면(`N=15 --redo l7_7`) 전체 중간 말 빠르기가 움직여서 **다른 문장의 고른 테이크까지 바뀌어요**(7문장이 바뀌고 시각표가 1.3초 밀린 적이 있어요). 한 번 넘긴 영상은 `PACE` 를 그때 출력된 값으로 고정하고, 다시 읽힌 뒤 바뀐 문장이 그 문장뿐인지 출력으로 확인해요. 그래야 부분 렌더(`--only`)가 맞아요

## 6. 여러 영상 · 여러 목소리를 한꺼번에 읽힐 때

- TTS 서버 쪽은 병렬로 읽혀도 되지만, **whisper 는 Mac 에서 한 프로세스만** 돌려요. `make_audio.py tts` 를 여러 개 동시에 돌리면 각자 whisper 모델을 올려서 16 GB Mac 이 스왑으로 느려져요(분당 19 → 5 테이크)
- 방법: 영상 · 목소리마다 테이크만 만들고(`import make_audio as M; M.make_takes(M.IDS, set())`, 병렬), 받아쓰기는 한 프로세스가 모든 `audio/tts_cache` 를 돌며 새 `.wav` 마다 `M.transcribe(path)` 를 불러 `.json` 을 써요. 완전히 무음인 테이크는 지워요(고를 때 오류가 나요). 다 끝나면 `make_audio.py tts` 를 영상마다 하나씩 돌려요(이때는 고르고 섞기만 해요)

## 7. TTS 모델

- Qwen3-TTS(1.7B Base, 복제)를 써요. 한국어 목소리로 Fish Audio S2-Pro · Chatterbox Multilingual V3 와 비교했을 때 Qwen 이 가장 나았어요(Chatterbox 는 "AI" 를 "아이" 로, Fish 는 남자 목소리 끝이 끊김)

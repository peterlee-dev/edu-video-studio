## 음성 만들기

대본은 `tools/script.py`(쓰는 문장 = 화면 · 자막 표기, 읽는 문장 = TTS가 읽는 표기: "Adaptive" → "어댑티브", "3번" → "삼 번", "2개" → "두 개", "수와 연산" → "수와연산"(띄우면 사이에서 길게 쉬어요)). 1차 검토 뒤로 읽는 문장에 구절마다 쉼표를 더 넣고("정작, 아이의"), 말 빠르기는 그대로(`SPEED = 1`) 읽혀요. 문장 사이 0.7초, 쪽 사이 +1.6초, 첫 문장은 1.0초에 시작하고, 쪽 넘김(1.3초)은 그 쪽 첫 문장 1.6초 전에 시작해요(`LEAD, GAP, SCENE_GAP, TURN`). 문장 끝 높낮이가 고르게 들리도록, 읽은 것 가운데 문장 끝 음높이가 다른 문장들과 비슷한 것을 골라요. `tools/make_audio.py tts`가 DGX Qwen3-TTS(`/v1/tts/clone`)로 문장마다 3번 읽히고, whisper로 받아써서 대본대로 읽은 것 중 말 빠르기가 가운데에 가까운 것을 골라요. `timeline.js`(장면 · 문장 · 단어 시각, `cues` = 그림 · 효과음이 따르는 단어)와 `audio/mix.wav`, `subtitles.srt`를 써요.

```bash
npm install
curl http://192.168.51.8:8095/health                                         # DGX TTS 서버
uv run --with numpy --with mlx-whisper python tools/make_audio.py tts        # 읽은 것은 audio/tts_cache/ 에 남아 바꾼 문장만 다시 읽어요
N=8 uv run --with numpy --with mlx-whisper python tools/make_audio.py tts --redo l8   # 한 문장만 8번 새로 읽기
```

## 확인 · 렌더

```bash
node tools/snap.mjs out/snaps --ends          # 쪽마다 다 그려진 화면
node render.mjs --workers 3                   # out/adaptive_diagnosis_v2_ko.mp4 (GPU)
node render.mjs --workers 3 --only 44-60      # 고친 구간만 다시 렌더
node render.mjs --cpu --workers 6             # GPU 가 없을 때: 예전 CPU 방식
```

`render.mjs` 는 GPU 로 렌더해요: Chrome 이 Metal 로 캔버스를 그리고, 브라우저 안의 하드웨어 H.264 인코더(WebCodecs → VideoToolbox)로 바로 압축해 조각을 다시 인코딩하지 않고 이어 붙여요(`jei-english-adaptive-diagnosis` 에서 가져옴). 예전 CPU 방식(SwiftShader + PNG + libx264)보다 훨씬 빠르고 메모리도 덜 써요. GPU 가 없는 컴퓨터는 `--cpu`.

- 장면: `index.html`의 `SC.intro` ~ `SC.outro`. 시각은 `Wd(문장, 단어)`(말한 단어의 시각)와 `TL.cues`로 내레이션에 묶여 있어요
- 제목 · 색: `content.js` (영상 편집기에서도 수정 가능)
